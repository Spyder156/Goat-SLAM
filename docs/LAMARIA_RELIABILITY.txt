Major finding checkpoint: dual-camera observation records and scale
------------------------------------------------------------------
User requested substantial diagnosis/repair and an explicit stop for discussion
after each major error, implementation or crossroads. This checkpoint therefore
packages the discovered structural error before changing the estimator.

Confirmed source defect: LocalMapping::ProcessNewKeyFrame checks keyframe-wide
MapPoint::IsInKeyFrame before adding each feature slot. For an existing point
seen in both cameras, adding cam0 makes that check true; cam1 is then skipped
and the established point is misclassified as a newly inserted stereo point
for recent-point culling. MapPoint actually stores separate left/right indices.
KeyFrame retains the right feature slot, while the landmark observation tuple
can lack it. BA reads the latter, so the slot is not equivalent to a BA factor.

Saved-state confirmation in fresh Short:2012 surviving map0 KF slots refer to
points whose observation dictionary has no observation from that camera at all;
2010 of these are cam1. This is a LOWER BOUND because camera-presence flags cannot
detect a missing observation in one KF if another KF recorded the same camera.
Baseline Short independently has1876 such slots,1873 fromcam1; Medium replay
has1260,1259 fromcam1. These are final-state consistency checks, not complete
historical counts or proof that this one defect explains the entire failure.

Concrete example: KF1937 at799.092200762s stores point370544 at cam0 pixel
(233.399,50.106) and cam1 pixel(235.564,362.626), but that live point's exported
observation history reports cam0 only.

Related places requiring the same per-camera invariant in a focused repair:
- ProcessNewKeyFrame: register each missing camera slot independently; add only
  points born in this KF to the recent list, once per point.
- MapPoint::AddObservation: repeated registration must not inflate nObs;
  resolve same-camera slot conflicts explicitly rather than silently overwriting.
- MapPoint::Replace: merge complementary camera slots when the survivor already
  has the other camera in that KF; current keyframe-wide check erases them.
- ORBmatcher::Fuse(KeyFrame,...,bRight): membership should be tested for the
  queried camera. Current keyframe-wide skip prevents adding the other camera.
No patches for these findings have been applied at this checkpoint.

436 cam0 and663 cam1 proposals using the production temporal gates.775 also pass
an independent bidirectional image-flow check. These are image correspondences,
not verified static-scene/3D inliers. Only2+5 proposals originate from previously
mapped landmarks, exactly matching the logged temporal seeds. The remaining1092
originate from unmapped features. This explains how plentiful red-red matches
